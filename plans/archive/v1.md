## Core design: the engine (everything sits on this)

`src/engine/` — pure TypeScript, no React, fully unit-tested.

- **State** (immutable, so every command is undoable and lessons can diff before/after):
  - `commits: Record<Id, Commit>` — `{ id, parents[], message, tree: Record<path, content>, author, time, flags? }`
  - `refs`: `heads/*`, `tags/*`, `remotes/<remote>/*`; `HEAD: { kind: 'ref', name } | { kind: 'detached', id }`
  - `index` and `workdir` (path → content), so `status`, `add`, `restore`, `reset --mixed/--hard`, `stash` and conflicts are real, not faked
  - `reflog` per ref and HEAD (this is what makes "recover a lost commit" lessons honest)
  - `upstreams` (branch → remote branch), `stash[]`, `merge/rebase/bisect/cherry-pick in-progress` state with conflict markers written into workdir
- **World** = several repos: `local`, `origin` (your GitHub repo), optional `upstream` (the repo you forked). Plus a **GitHub layer**: forks, pull requests (head, base, commits, reviews, status, merge method: merge / squash / rebase), branch protection, and simulated Actions runs.
- **Commands** = `run(world, input) → { world, output, events[] }`. A small shell parser handles quotes and `&&`. `events` (commit-created, ref-moved, HEAD-moved, objects-pushed, pr-opened…) drive the animations, so the graph never guesses what changed.
- **Deterministic short hashes** (seeded), so lesson text can say "commit `a1f3c9e`" and it's true every time.
- Supported: `init clone status add commit(-m -a --amend) log(--oneline --graph --all) diff branch(-d -D -m) switch checkout(-b, detached) restore merge(ff, --no-ff, 3-way, conflicts, --abort) rebase(--onto, --continue/--abort, -i via a UI todo-list editor) cherry-pick revert reset(--soft --mixed --hard) reflog stash(push pop list drop) tag remote fetch pull(--rebase) push(-u --force --force-with-lease, rejected non-ff) bisect(start good bad reset)`; file helpers `ls cat touch echo > >> edit rm`; GitHub via `gh repo fork / gh pr create / gh pr review / gh pr merge` **and** clickable GitHub-style buttons.
- Correctness proof: a Vitest suite of scenario tests, each written against what real Git does (I'll check edge cases against real `git` in a temp folder while writing the tests).

## Decision log
| Decision | Chosen | Why |
| --- | --- | --- |
| Engine state | Immutable world object, commands as pure functions returning events | Undo/time travel, lesson goal checks, testability, animation without diffing guesses |
| Graph | SVG + Framer Motion, custom lane layout | Brief's choice; layout is small enough to own |
| Hashes | Deterministic | Lesson text stays true |
| Interactive rebase | UI todo-list editor, not a fake vim | Teaches the concept without a text-editor detour |
| Persistence | localStorage, versioned key, all access in try/catch | No backend (brief) |
| Tests | Vitest for engine (TDD), Playwright smoke | Engine correctness is an anti-goal-level risk |
| Name | Branchwise, repo ohenemanaf/BRANCHWISE, folder D:\ALL_PROJECTS\BRANCHWISE | User choice 2026-11-26 |
| Deploy | User imports the repo in the Vercel dashboard; pushes auto-deploy | User choice; Vercel CLI not installed |
| Submodules / Actions | Animated walkthroughs + a few working commands | User choice; engine effort goes to rebase/cherry-pick/reflog/bisect |
| Cheat codes | All open, with "learned" badges from progress | User choice; works as a bookmarkable reference |
